# 基金分析 Agent（Java 版）第一部分开发指引

> 阶段：Phase 0——项目初始化与基础架构  
> 目标：搭建可持续开发、可测试、可观测的 Maven 多模块骨架，并使用 Mock 数据跑通第一条基金查询链路。  
> 本阶段不接真实行情、不实现复杂 Agent、不引入消息队列。

## 1. 本阶段交付结果

完成后，项目必须具备以下能力：

1. Spring Boot 应用可以一键启动。
2. 应用可以连接本机已经安装的 MySQL；Redis 等辅助组件可以通过 Docker Compose 启动。
3. 模块依赖方向清晰，不允许 Controller 直接访问 Mapper。
4. 通过 `MockFundDataProvider` 查询基金基本信息与一段历史净值。
5. 提供基金详情、历史净值、系统健康检查三个接口。
6. 所有响应都包含 `requestId`，日志可按请求追踪。
7. 单元测试和最小集成测试可以运行。
8. 配置文件不包含真实密码、Token 或模型密钥。

## 4. 模块依赖规则

```text
fund-bootstrap
  ├─ fund-interface
  ├─ fund-infrastructure
  └─ fund-observability

fund-interface
  └─ fund-application

fund-application
  └─ fund-domain

fund-infrastructure
  └─ fund-domain

fund-agent-runtime
  ├─ fund-application
  └─ fund-domain

fund-scheduler
  └─ fund-application
```

强制规则：

- `fund-domain` 不依赖 Spring、MyBatis、Redis、HTTP 客户端或模型 SDK。
- Controller 只做参数校验、身份获取、调用 Application Service 和响应转换。
- Application Service 负责编排用例和事务边界，不包含第三方 HTTP 细节。
- Infrastructure 实现 Domain 定义的 Repository 和 Provider 端口。
- Agent 后续只能通过 Application 暴露的 Tool 用例访问业务数据，不能直接访问 Mapper。

## 5. 第一条业务链路

本阶段只实现：根据基金代码查询基本信息和历史净值。

```text
GET /api/v1/funds/{fundCode}
        ↓
FundQueryController
        ↓
FundQueryApplicationService
        ↓
FundDataProvider（Domain 端口）
        ↓
MockFundDataProvider（Infrastructure 实现）
```

### 5.1 Domain 模型

建议先定义以下不可变模型：

```java
public record FundCode(String value) {
    public FundCode {
        if (value == null || !value.matches("\\d{6}")) {
            throw new IllegalArgumentException("基金代码必须是 6 位数字");
        }
    }
}

public record FundProfile(
    FundCode code,
    String name,
    String fundType,
    String managementCompany,
    String fundManager,
    LocalDate establishedDate,
    Instant collectedAt,
    String dataSource
) {}

public record NavPoint(
    LocalDate navDate,
    BigDecimal unitNav,
    BigDecimal accumulatedNav,
    Instant collectedAt,
    String dataSource
) {}
```

金额、净值和收益率统一使用 `BigDecimal`，禁止使用 `double` 保存需要精确展示或复算的金融数值。

### 5.2 Provider 端口

```java
public interface FundDataProvider {
    Optional<FundProfile> getProfile(FundCode fundCode);

    List<NavPoint> getNavHistory(
        FundCode fundCode,
        LocalDate startDate,
        LocalDate endDate
    );
}
```

Provider 返回的数据必须携带 `dataSource` 和 `collectedAt`。后续接入真实数据源时，不能丢失数据来源与采集时间。

### 5.3 Application Service

```java
public interface FundQueryUseCase {
    FundProfileResult getFundProfile(String fundCode);

    FundNavHistoryResult getNavHistory(
        String fundCode,
        LocalDate startDate,
        LocalDate endDate
    );
}
```

Application Service 负责：

- 将字符串转换为 `FundCode`。
- 检查日期范围是否合法。
- 调用 Provider。
- 将“数据不存在”转换为稳定的业务错误码。
- 返回适合 Interface 层转换的结果对象。

### 5.4 REST API

```text
GET /api/v1/funds/{fundCode}
GET /api/v1/funds/{fundCode}/nav?startDate=2026-01-01&endDate=2026-08-01
GET /actuator/health
```

统一响应结构：

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "01J...",
  "data": {}
}
```

错误响应示例：

```json
{
  "code": "FUND_NOT_FOUND",
  "message": "未找到基金：000001",
  "requestId": "01J...",
  "data": null
}
```

HTTP 状态和业务错误码需要同时正确：参数错误使用 400，未认证使用 401，无权限使用 403，资源不存在使用 404，数据源暂不可用使用 503。

## 6. 基础设施配置

### 6.1 本机 MySQL

MySQL 不使用 Docker，直接连接开发机上已经安装的 MySQL 8。建议准备相互隔离的数据库：

```text
jijing_agent          本地开发数据库
jijing_agent_test     自动化测试数据库
```

要求：

- 默认地址使用 `127.0.0.1:3306`，用户名通过本地配置提供。
- 数据库密码只放在操作系统环境变量或不提交 Git 的 `application-local-private.yml` 中。
- Git 只提交无秘密的配置模板，例如 `${MYSQL_PASSWORD}`，不得提交真实密码。
- 测试库与开发库分离，测试不得清空或修改开发库数据。
- 启动时通过 Flyway 执行版本化数据库迁移，禁止依赖手工改表。

本地配置示例：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/jijing_agent?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: ${MYSQL_USERNAME:root}
    password: ${MYSQL_PASSWORD}
```

开发者在自己的机器上设置 `MYSQL_PASSWORD`，真实值不写入项目文件、README、日志或提交记录。

### 6.2 Docker Compose

Docker Compose 不启动 MySQL，只负责可替换的辅助服务：

```text
Redis 7
Prometheus（可选，建议本阶段加入）
```

要求：

- Redis 等服务配置健康检查。
- 数据卷使用项目目录下的明确子目录或命名卷。
- 密码从本地环境变量读取，仓库只提交 `.env.example`。
- 不使用默认弱密码作为生产配置。

### 6.3 Spring Profile

```text
application.yml          公共配置
application-local.yml    本地开发
application-test.yml     自动化测试
application-prod.yml     生产占位，只引用环境变量
```

本地开发默认启用 MockProvider：

```yaml
fund:
  provider:
    type: mock
```

未来接入真实数据源时使用条件装配：

```java
@ConditionalOnProperty(name = "fund.provider.type", havingValue = "mock")
```

## 7. 横切能力

### 7.1 Request ID

实现 `OncePerRequestFilter`：

1. 优先读取调用方传入的 `X-Request-Id`。
2. 不存在时生成 UUID/ULID。
3. 写入 MDC。
4. 写入响应头和统一响应体。
5. 请求结束后清理 MDC，防止线程复用污染。

### 7.2 异常处理

使用 `@RestControllerAdvice`，至少处理：

- 参数绑定与校验错误。
- 业务异常。
- 数据源异常。
- 未知异常。

未知异常不能向客户端返回堆栈、SQL、Token、第三方响应全文。

### 7.3 日志

日志必须包含：

```text
requestId / operation / fundCode / latencyMs / result / errorCode
```

禁止记录：

```text
API Key / 密码 / 完整用户持仓 / 第三方原始敏感响应
```

### 7.4 健康检查

Actuator 至少暴露：

```text
/actuator/health
/actuator/prometheus
```

生产环境应通过安全配置限制管理端点访问；本阶段只验证端点能够工作。

## 8. 测试要求

### 8.1 Domain 单元测试

- 合法和非法 `FundCode`。
- `BigDecimal` 精度与序列化。
- 日期范围边界。

### 8.2 Application 单元测试

- 基金存在时返回正确结果。
- 基金不存在时返回 `FUND_NOT_FOUND`。
- Provider 异常映射为 `DATA_SOURCE_UNAVAILABLE`。
- 非法日期不调用 Provider。

### 8.3 Interface 测试

使用 MockMvc 验证：

- URL、参数、HTTP 状态。
- 统一响应结构。
- `requestId` 同时出现在响应头和响应体。
- 错误响应不泄漏内部异常。

### 8.4 集成测试

集成测试连接本机独立的 `jijing_agent_test` 数据库，并使用隔离的 Redis 测试库，验证：

- Spring 容器能启动。
- 数据库迁移成功。
- Redis 连接正常。
- `/actuator/health` 正常。

测试启动前必须校验当前数据库名为 `jijing_agent_test`，不满足时直接终止测试，避免误操作开发库。后续 CI 环境可以单独引入 Testcontainers，但不影响本地 MySQL 的部署方式。

## 9. 推荐开发顺序

按以下顺序提交，每一步保持可编译：

1. 创建父 POM、模块 POM 和依赖规则。
2. 创建 Bootstrap 启动类与配置文件。
3. 创建 Domain 模型和 `FundDataProvider` 端口。
4. 创建 MockProvider 与固定测试数据。
5. 创建 Application Use Case。
6. 创建 Controller、DTO、统一响应与异常处理。
7. 增加 Request ID、MDC 与访问日志。
8. 配置本机 MySQL、Redis Docker Compose 和 Flyway 数据库迁移。
9. 增加 Actuator、Prometheus 指标。
10. 补齐单元测试与集成测试。

建议提交信息：

```text
chore: initialize multi-module project
feat: add fund domain models and provider port
feat: implement mock fund query flow
feat: add unified api response and error handling
feat: add request tracing and health metrics
test: add fund query integration tests
```

## 10. 完成标准

只有同时满足以下条件，Phase 0 才算完成：

- `mvn clean verify` 通过。
- 本机 MySQL 可连接，`docker compose up -d` 后 Redis 等辅助服务健康。
- 应用在空数据库环境能自动完成初始化并启动。
- 基金详情和净值接口可以返回 Mock 数据。
- 非法基金代码、非法日期和不存在基金都有明确错误码。
- Controller 没有直接依赖 Mapper、Redis 客户端或第三方 Provider 实现。
- Git 仓库中不存在真实密钥和密码。
- README 包含启动、测试、接口访问和常见问题说明。

## 11. 本阶段暂不实现

为了控制范围，以下内容留到后续阶段：

- 真实基金数据源和爬虫。
- 收益率、回撤、持仓重合度等完整指标引擎。
- 用户登录、真实持仓与权限体系。
- Agent、Tool Calling、DAG、Memory、HITL。
- SSE 流式回答。
- 定时任务、消息队列和通知推送。
- RAG、多 Agent 和 MCP。

这些功能需要建立在稳定的数据模型、模块边界和测试基础上。
