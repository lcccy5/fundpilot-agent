# 基金分析 Agent（Java 版）第三部分开发指引

> 阶段：Phase 2——基金指标计算与多基金对比  
> 前置：Phase 1 已完成真实数据采集边界、MySQL 净值事实表、Redis 缓存、幂等同步和数据来源追踪。  
> 目标：把可信净值序列转换为可复算、可解释、可测试的收益与风险指标，并支持多基金同口径比较。  
> 本阶段不接入大模型，不生成买卖建议，不根据单一综合分数推荐基金。

> 实施状态（2026-08-23）：本阶段核心代码已经落地并通过 `mvn clean verify`、MySQL 8 V4 迁移、快照幂等 upsert 及真实启动 API 验证。当前 Mock 数据只有 5 个观测点，因此年化波动率和夏普比率会按设计返回 `INSUFFICIENT_OBSERVATIONS`；交易日历未导入时覆盖率返回 `UNKNOWN`。真实交易日历数据接入和真实基金 Provider 凭证属于数据源配置，不在代码中伪造。

## 1. 本阶段的项目价值

Phase 1 解决“数据从哪里来、是否可靠”；Phase 2 解决“如何从数据得到确定性结论”。

完整链路：

```text
FundNavRepository
        ↓
NavSeriesBuilder（排序、去重、口径选择）
        ↓
MetricCalculator（纯 Java 计算）
        ↓
MetricValidation（样本数、覆盖率、边界校验）
        ↓
FundMetricSnapshot / Redis
        ↓
MetricsQueryUseCase / FundComparisonUseCase
        ↓
REST API
        ↓
后续 Agent Tools
```

指标计算必须是确定性代码。未来大模型只负责选择工具、解释结果和组织语言，不能自己心算收益率、回撤或夏普比率。

## 2. 本阶段交付结果

完成后必须具备：

1. 对任意合法日期区间计算区间收益率。
2. 对满足样本要求的净值序列计算年化收益率、年化波动率、最大回撤、夏普比率。
3. 返回最大回撤开始日、谷底日、恢复日。
4. 输出上涨天数、下跌天数、胜率和最佳/最差单日收益。
5. 输出样本数、预期交易日数、数据覆盖率和净值口径。
6. 支持 2～10 只基金同区间、同口径比较。
7. 标准周期指标可以预计算并写入 MySQL，任意区间按需计算并写入 Redis。
8. 计算结果携带算法版本和数据版本，底层净值变化后旧缓存自动失效。
9. 数据不足时返回明确的 `UNAVAILABLE` 和原因，不返回伪造的 0。
10. 使用已知向量、边界用例和性质测试验证公式。

## 3. 先明确“收益率”的净值口径

基金收益率不能只返回一个数字，还必须说明使用了哪条净值序列。

### 3.1 三种口径

```text
UNIT_NAV
单位净值变化，只反映单位净值价格变化，分红除息会造成跳变。

ACCUMULATED_NAV
累计净值变化，考虑历史分红累计值，但不等价于严格的现金分红再投资总回报。

ADJUSTED_NAV
复权净值，按分红再投资规则调整；具备可靠分红数据后才可使用。
```

Phase 2 默认规则：

1. 请求显式指定 `navBasis` 时按指定口径计算。
2. 未指定时优先使用完整的 `ACCUMULATED_NAV`。
3. 累计净值缺失时降级为 `UNIT_NAV`，响应必须返回实际口径。
4. 没有可靠分红与复权数据时，不得把结果命名为“投资者总回报率”。
5. 多基金比较必须使用同一个净值口径；任何基金不满足时整次比较失败或统一降级，不能混算。

### 3.2 数据模型调整

`NavPoint` 增加可选字段：

```java
BigDecimal adjustedNav;
NavStatus navStatus;       // CONFIRMED / ESTIMATED / CORRECTED
```

本阶段计算只接受 `CONFIRMED` 和 `CORRECTED`，不使用盘中估算净值。

建议增加独立模块：

```text
fund-analytics/
├─ pom.xml
└─ src/main/java/com/jijing/fund/analytics/
   ├─ model/
   ├─ calculator/
```

依赖方向：

```text
fund-analytics → fund-domain
fund-application → fund-domain + fund-analytics
fund-infrastructure → fund-domain
fund-interface → fund-application
```

`fund-analytics` 必须保持纯 Java：

- 不依赖 Spring。
- 不依赖 MyBatis。
- 不访问 Redis、MySQL 或 HTTP。

- 同样输入和算法版本必须得到同样结果。

这样既方便单元测试，也可以将指标引擎独立用于离线任务或后续 Agent Tool。

## 6. 指标公式与统一约定

内部收益率使用小数：`0.1234` 表示 `12.34%`。Interface 层可以额外格式化显示，但 Domain 和数据库禁止混用 `12.34` 与 `0.1234`。

统一常量：

```text
TRADING_DAYS_PER_YEAR = 252
CALENDAR_DAYS_PER_YEAR = 365.2425
MIN_VOLATILITY_RETURNS = 20
MIN_SHARPE_RETURNS = 60
MIN_ANNUALIZATION_DAYS = 365
DEFAULT_ANNUAL_RISK_FREE_RATE = 0
MATH_CONTEXT = DECIMAL128
OUTPUT_SCALE = 8
ROUNDING_MODE = HALF_UP
```

无风险利率必须是配置和响应字段的一部分，不能隐藏在代码中。第一版默认 0，仅用于保证结果可复算；后续可接入合法利率数据源。

### 6.1 日收益率

对相邻两个有效净值：

```text
r(t) = NAV(t) / NAV(t-1) - 1
```

不能把自然日缺口补成若干个 0 收益日。周末、节假日没有净值属于正常情况。

### 6.2 区间累计收益率

```text
cumulativeReturn = endingNav / beginningNav - 1
```

最低要求：2 个有效观测点。

### 6.3 年化收益率

```text
years = calendarDays / 365.2425
annualizedReturn = (endingNav / beginningNav)^(1 / years) - 1
```

规则：

- 区间少于 365 个自然日时返回 `PERIOD_TOO_SHORT`。
- 使用实际首尾净值日期，而不是请求日期。
- 结果必须标注 `GEOMETRIC_ANNUALIZATION`。
- 不允许把 30 天收益简单乘以 12 冒充年化收益。

### 6.4 年化波动率

使用日简单收益率的样本标准差：

```text
mean = sum(r) / n
sampleVariance = sum((r - mean)^2) / (n - 1)
dailyVolatility = sqrt(sampleVariance)
annualizedVolatility = dailyVolatility * sqrt(252)
```

最低要求：20 个日收益观测，即至少 21 个净值点。

### 6.5 最大回撤

遍历净值序列并维护历史高点：

```text
peak(t) = max(NAV(0)...NAV(t))
drawdown(t) = NAV(t) / peak(t) - 1
maxDrawdown = min(drawdown(t))
```

最大回撤返回非正数，例如 `-0.2531` 表示回撤 25.31%。同时返回：

```text
peakDate       回撤前高点日期
troughDate     最大回撤谷底日期
recoveryDate   后续首次恢复至前高点的日期；未恢复则为 null
```

净值持续上涨时最大回撤为 0，峰值和谷底可以都取首个观测日，恢复日为空。

### 6.6 夏普比率

使用日超额收益计算：

```text
dailyRiskFree = (1 + annualRiskFreeRate)^(1 / 252) - 1
dailyExcess(t) = dailyReturn(t) - dailyRiskFree
sharpe = mean(dailyExcess) / sampleStdDev(dailyReturn) * sqrt(252)
```

规则：

- 最低 60 个日收益观测。
- 波动率为 0 时返回 `ZERO_VOLATILITY`，不能返回无穷大。
- 响应必须返回所用年化无风险利率。
- 多基金比较必须使用相同无风险利率。

### 6.7 上涨比例和极值

```text
positiveDayRatio = positiveReturnCount / validDailyReturnCount
bestDailyReturn = max(dailyReturns)
worstDailyReturn = min(dailyReturns)
```

收益恰好为 0 的交易日不计入上涨日，也不计入下跌日，但计入有效收益样本总数。

## 7. BigDecimal 与浮点计算边界

使用规则：

- 数据库存储、API 输入输出、净值比值和累计收益使用 `BigDecimal`。
- 加减乘除必须传入统一 `MathContext` 或舍入规则。
- 不使用 `new BigDecimal(double)`；需要转换时使用 `BigDecimal.valueOf(double)`。
- `sqrt` 可使用 `BigDecimal.sqrt(MathContext)`。
- 非整数指数年化计算可以在封装的 `StatMath` 中使用 `StrictMath.pow`，随后使用 `BigDecimal.valueOf` 转换。
- 浮点计算只能存在于 `fund-analytics` 的数学实现内部，不能泄漏到 Domain、数据库和 API DTO。

所有计算函数都要有误差容忍断言，例如 `1E-8`，不能用 `BigDecimal.equals` 验证不同 scale 的统计结果。

## 8. 数据覆盖率和交易日历

### 8.1 为什么需要覆盖率

两个首尾净值相同的序列，如果一个有 250 个有效点、另一个只有 20 个点，它们的波动率可信度完全不同。因此响应必须携带覆盖率。

### 8.2 交易日历表

使用 Flyway `V4__create_trading_calendar_and_metric_tables.sql`：

```sql
CREATE TABLE trading_calendar (
    market_code VARCHAR(16) NOT NULL,
    trade_date DATE NOT NULL,
    trading_day TINYINT(1) NOT NULL,
    source_name VARCHAR(64) NOT NULL,
    collected_at DATETIME(3) NOT NULL,
    PRIMARY KEY (market_code, trade_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

本阶段市场代码使用 `CN`。交易日历也必须有数据来源，不能只靠“周一到周五”判断，因为法定节假日和调休需要正确处理。

### 8.3 覆盖率

```text
coverage = actualObservationCount / expectedTradingDayCount
```

建议规则：

```text
coverage >= 0.98       COMPLETE
0.90 <= coverage < .98 PARTIAL
coverage < 0.90        INSUFFICIENT
无交易日历             UNKNOWN
```

当覆盖率 `INSUFFICIENT` 时：

- 区间累计收益仍可返回，但附带质量警告。
- 波动率、夏普比率等路径相关指标返回 `LOW_DATA_COVERAGE`。
- 不允许自动插值或用前值填充缺失交易日。

## 9. 数据版本与算法版本

缓存失效不能只依赖 TTL。

### 9.1 数据版本

为 `fund` 表增加：

```sql
data_revision BIGINT NOT NULL DEFAULT 0
latest_nav_date DATE NULL
```

每次净值同步事务实际插入或修订数据后：

```text
data_revision = data_revision + 1
latest_nav_date = 当前最大净值日期
```

如果同步结果与数据库完全相同，不增加版本。

### 9.2 算法版本

```text
fund-metrics-v1
```

以下变化必须升级算法版本：

- 公式变化。
- 年化天数约定变化。
- 最低样本数变化。
- 净值口径选择规则变化。
- 交易日缺失处理变化。
- 舍入精度变化。

### 9.3 结果身份

```text
fundCode + startDate + endDate + navBasis
+ riskFreeRate + dataRevision + algorithmVersion
```

以上字段共同决定一个指标结果，不能只用基金代码作为缓存 Key。

## 10. 指标快照表

只持久化标准周期，任意日期区间只缓存不落表。

标准周期：

```text
1M / 3M / 6M / 1Y / 3Y / 5Y / YTD / MAX
```

```sql
CREATE TABLE fund_metric_snapshot (
    id BIGINT NOT NULL AUTO_INCREMENT,
    fund_code VARCHAR(6) NOT NULL,
    period_code VARCHAR(16) NOT NULL,
    actual_start_date DATE NOT NULL,
    actual_end_date DATE NOT NULL,
    nav_basis VARCHAR(32) NOT NULL,
    observation_count INT NOT NULL,
    coverage_rate DECIMAL(10,8) NULL,
    cumulative_return DECIMAL(18,8) NULL,
    annualized_return DECIMAL(18,8) NULL,
    annualized_volatility DECIMAL(18,8) NULL,
    max_drawdown DECIMAL(18,8) NULL,
    sharpe_ratio DECIMAL(18,8) NULL,
    positive_day_ratio DECIMAL(18,8) NULL,
    risk_free_rate DECIMAL(18,8) NOT NULL,
    data_revision BIGINT NOT NULL,
    algorithm_version VARCHAR(64) NOT NULL,
    calculated_at DATETIME(3) NOT NULL,
    created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
        ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_metric_identity (
        fund_code, period_code, nav_basis,
        data_revision, algorithm_version
    ),
    KEY idx_metric_latest (fund_code, period_code, calculated_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

快照表是计算结果缓存，不是事实来源。可以安全重建，不能反向修改原始净值。

## 11. Calculator 设计

建议拆成小型无状态计算器：

```text
DailyReturnCalculator
CumulativeReturnCalculator
AnnualizedReturnCalculator
VolatilityCalculator
MaximumDrawdownCalculator
SharpeRatioCalculator
ReturnDistributionCalculator
FundMetricsCalculator        只负责组合上述计算器
```

统一接口示例：

```java
public interface MetricCalculator<T> {
    T calculate(NavSeries series, CalculationContext context);
}

public record CalculationContext(
    BigDecimal annualRiskFreeRate,
    int tradingDaysPerYear,
    String algorithmVersion,
    Clock clock
) {}
```

禁止：

- 每个计算器自己查询数据库。
- 每个计算器采用不同舍入方式。
- 捕获所有异常后返回 0。
- 使用并行流处理几十到几百个净值点。
- 在 Calculator 中读取系统时间，时间由 `CalculationContext` 提供。

## 12. Application Use Case

### 12.1 单基金指标

```java
public interface FundMetricsQueryUseCase {
    FundMetricsResult calculate(
        String fundCode,
        LocalDate startDate,
        LocalDate endDate,
        String navBasis
    );
}
```

执行顺序：

```text
校验基金代码和日期
  → 读取 fund.dataRevision
  → 查询指标缓存
  → 查询净值与交易日历
  → 构造 NavSeries
  → 执行纯函数指标计算
  → 写入缓存
  → 返回结果
```

### 12.2 多基金比较

```java
public interface FundComparisonUseCase {
    FundComparisonResult compare(
        List<String> fundCodes,
        LocalDate startDate,
        LocalDate endDate,
        String navBasis
    );
}
```

规则：

- 最少 2 只、最多 10 只。
- 去重后不足 2 只返回参数错误。
- 所有基金使用相同实际比较区间。
- 共同开始日取各基金首个有效日中的最晚日期。
- 共同结束日取各基金最后有效日中的最早日期。
- 共同区间不存在时返回 `NO_OVERLAPPING_PERIOD`。
- 每只基金仍返回自己的样本数和覆盖率。
- 只提供指标排序，不输出“最佳基金”“建议买入”。

比较结果可以给出：

```text
累计收益率降序排名
年化波动率升序排名
最大回撤绝对值升序排名
夏普比率降序排名
```

指标不可用的基金排在该指标末尾，并显示不可用原因。

### 13.3 错误码

| 业务码 | HTTP | 含义 |
| --- | ---: | --- |
| INVALID_ARGUMENT | 400 | 代码、日期或净值口径非法 |
| FUND_NOT_FOUND | 404 | 基金不存在 |
| NAV_DATA_NOT_READY | 409 | 没有足够净值数据 |
| NO_OVERLAPPING_PERIOD | 422 | 多基金没有公共比较区间 |

| METRIC_CALCULATION_FAILED | 500 | 未预期的计算错误 |

单个指标样本不足不一定让整个 API 失败，应在该指标内部返回 `UNAVAILABLE`。

## 14. Redis 缓存

```text
jijing:fund:metrics:{fundCode}:{dataRevision}:{algorithmVersion}:
    {navBasis}:{startDate}:{endDate}:{riskFreeRate}

jijing:fund:comparison:{comparisonHash}
```

规则：

- 任意区间指标 TTL 2 小时并增加随机抖动。
- 标准周期优先读取 MySQL 快照。
- `dataRevision` 变化后旧 Key 自然失效，无需扫描删除。
- 比较 Hash 必须先对基金代码去重、排序并规范化日期。
- Redis 不可用时现场计算，接口仍然可用。
- 不缓存 `METRIC_CALCULATION_FAILED`。
- 数据不足结果可以短缓存 5 分钟，避免重复查询空数据。

## 15. 标准周期预计算

在 `fund-scheduler` 增加：

```text
FundMetricSnapshotScheduler
```

默认在净值同步任务结束后执行，或工作日凌晨 03:30 执行：

```text
查询 dataRevision 有变化的基金
  → 分页读取
  → 计算标准周期
  → upsert fund_metric_snapshot
  → 记录任务审计和指标
```

要求：

- 每只基金独立事务。
- 使用与数据同步不同的锁 Key。
- 仅重算版本变化的基金。
- 单只失败不能中断整批。
- 失败保留上一版本快照，但查询时不能把旧版本冒充新版本。
- 本阶段不引入消息队列，先使用定时扫描保证简单可靠。

## 16. 为后续 Agent 提供稳定工具边界

本阶段不实现 Agent，但需要保证未来能直接包装成 Tool：

```text
get_fund_metrics
compare_funds
get_drawdown_detail
```

Tool 只能调用 Application Use Case，不能直接调用 Calculator 或 Repository。

未来 Agent 输出应能区分：

```text
FACT
原始净值、日期、数据来源。

CALCULATION
指标值、公式版本、净值口径、样本数。

INTERPRETATION
大模型对指标的自然语言说明，不属于事实数据。
```

指标 API 必须返回足够元数据，使 Agent 可以引用证据，而不是只拿到一个数字。

## 17. 测试策略

### 17.1 已知向量测试

至少准备以下固定序列：

```text
恒定序列：1, 1, 1, 1
严格上涨：1, 1.1, 1.2, 1.3
严格下跌：1.3, 1.2, 1.1, 1.0
先涨后跌：1, 1.2, 1.5, 1.1, 1.3
包含恢复：1, 1.5, 1.0, 1.5, 1.6
单观测点
重复日期
缺失交易日
净值为 0 或负数
```

验证：

- 严格上涨序列最大回撤为 0。
- 严格下跌序列峰值为首日、谷底为末日。
- 恢复日期必须是首次重新达到旧峰值的日期。
- 恒定序列波动率为 0，夏普比率不可用。
- 首尾收益与手工计算一致。
- 输入顺序打乱后，构造出的合法序列结果一致。

### 17.2 性质测试

建议引入 jqwik：

- 所有合法序列的最大回撤 `<= 0`。
- 所有合法序列的波动率 `>= 0`。
- 给全部净值乘以同一个正常数，收益率和回撤不变。
- 向序列末尾追加相同净值，不改变累计收益。
- 完全递增序列的最大回撤为 0。
- 结果中不能出现 NaN 或 Infinity。

### 17.3 Application 测试

- 缓存命中不查询 Repository。
- 数据版本变化后不复用旧缓存。
- 任意区间不写快照表。
- 标准周期正确读取/更新快照。
- Redis 异常时现场计算。
- 多基金使用共同区间。
- 不同净值口径不能混合比较。

### 17.4 MySQL 集成测试

使用 `jijing_agent_test`：

- V4 迁移成功。
- 指标快照唯一键正确。
- 相同版本重复计算能够幂等 upsert。
- 数据版本增加后保留新旧快照，可查询最新匹配版本。
- 测试库保护仍然生效。

## 18. 性能目标

在本机开发环境，以单只基金 10 年、约 2500 个净值点为基准：

```text
单基金全指标纯计算 P95 < 20 ms
数据库读取 + 计算 P95 < 100 ms
缓存命中 P95 < 20 ms
10 只基金比较 P95 < 500 ms
```

先通过 JMH 或简单基准测试测量，再决定是否优化。禁止为了几千个数据点提前引入 Spark、Flink 或 GPU。

多基金比较可以使用有界线程池并行读取与计算，但必须：

- 最大并行度可配置，默认不超过 4。
- 保持输出顺序稳定。
- 单只基金失败不泄漏线程和上下文。
- MDC/requestId 能够传递或明确重新建立。

## 21. 完成标准

- `mvn clean verify` 全部通过。
- V4 在空测试库和已有 V1～V3 数据库上都能迁移。
- 所有公式都有固定向量测试和边界测试。
- 最大回撤返回峰值、谷底、恢复日期。
- 样本不足、覆盖率不足、零波动不会产生 NaN、Infinity 或伪造的 0。
- 单基金和多基金接口返回净值口径、样本数、覆盖率、数据版本和算法版本。
- 数据版本变化后不会返回旧指标缓存。
- Redis 停止时指标仍能通过 MySQL 现场计算。
- 标准周期快照可以幂等重建。
- 10 只基金比较具有稳定输出顺序和明确的公共区间。
- API 和日志不包含“建议买入”“保证收益”等投资建议表述。

## 22. 本阶段暂不实现

- 基准指数超额收益、Alpha、Beta、信息比率。
- Sortino、Calmar、VaR、CVaR 等扩展指标。
- 基金持仓重合度和风格漂移。
- 用户真实持仓收益、现金流和 XIRR。
- 基金综合打分和推荐策略。
- 大模型、Agent、Tool Calling、Plan/DAG、Memory、HITL。
- 新闻、公告、研报 RAG。

先把少量核心指标做正确、可解释、可复算，再增加指标数量。

## 23. 口径参考

- [GIPS 计算方法手册](https://www.gipsstandards.org/wp-content/uploads/2021/04/gips-standards-handbook-firms.pdf)强调年化口径和方法变更披露；本项目将年化约定、数据版本和算法版本都放入结果元数据。
- [SEC 披露材料中的总回报定义示例](https://www.sec.gov/Archives/edgar/data/917100/000110465925022141/tm257937d3_ex99-19xex2.htm)包含分配再投资假设；只有单位净值或累计净值时，本项目不会将其错误命名为严格总回报。
- Java 金额与精确小数使用 [`BigDecimal`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/math/BigDecimal.html)，平方根、幂和舍入必须显式传入 `MathContext` 或舍入规则。
