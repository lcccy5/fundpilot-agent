# FundPilot 金融 App 前端改造与验收

验收日期：2026-10-03。此次改造覆盖 11 个用户页面，沿用 React、TypeScript 和原有路由，没有新增 UI 框架。

## 页面与结构

- `fund-web/components/AppShell.tsx`：电脑侧栏、手机顶栏与底栏。手机入口为研究、自选、组合、我的；登录和注册使用独立认证布局。
- `fund-web/components/FinanceUI.tsx`：状态面板、资产指标、状态标签，以及金额和涨跌展示函数。组件只展示页面传入的数据，不调用业务接口。
- `fund-web/app/globals.css`：统一的设计变量、公共组件和响应式规则。旧的 research-theme、product-layout 文件已归并；布局只加载这一份公共样式。
- `fund-web/app/arena/arena.css`：多 Agent 页面专属布局，颜色沿用公共变量。
- 各页面的 `page.tsx`：保留接口请求与表单逻辑，采用清晰排版与中文注释。

手机研究页面通过 CSS 切换“基金概览 / AI 研究”，两个区域保持挂载，因此切换不会丢失输入、对话或运行状态。手机持仓和交易列表逐行标注字段，保留全部列。

## 本轮修复

- 基金、组合、任务和报告使用请求序号，旧请求不能覆盖新选择。
- 导入文件在检查与提交期间禁止替换；有错误行时禁止确认，提交保留文件校验值。
- 任务“已完成”和“正文可阅读”分别显示，正文未就绪时允许重新读取。
- 自选、任务、通知、问卷、报告范围区分加载、空数据和读取失败。
- 风险问卷提交时定位缺失题目；选择空选项会清除答案，不会被转换成数值零。
- 登录与注册保留站内返回路径，拒绝站外地址、反斜杠和控制字符。
- 修复原有 8 个 React Hooks lint 错误；完整 lint 结果为零错误、零警告。

## 组合数据口径：按真实 Java 接口修正

原页面将 `/returns` 当作资产摘要使用，但该接口实际返回收益率；真实持仓的基金代码也以 `{ value }` 形式返回。此次前端适配现有接口，不修改 Java 接口。

| 页面信息 | 来源与处理 |
| --- | --- |
| 当前持仓 | `/positions` 的 `fundCode.value`、`confirmedShares` |
| 组合总资产 | `/valuation` 的 `totalValue` |
| 持仓浮动盈亏 | `/valuation` 的 `unrealizedProfit`，明确为浮盈亏 |
| 估值日期 | `/valuation` 的 `asOfDate` |
| 资金加权年化收益率 | `/returns` 的 `moneyWeightedReturn`，展示时乘 100；标注 XIRR |
| 持仓市值、浮盈亏 | 估值中的 `value`；浮盈亏为市值减剩余成本，仅用于展示 |
| 集中度 | `/risk` 返回 0～1 的比例，展示时转换为百分数 |

因此，最终资产卡片采用“组合总资产 / 持仓浮动盈亏 / 资金加权年化收益率”，没有将浮盈亏写成累计收益，也没有将年化收益率写成累计收益率。缺失数据展示“—”，真实零值保留。
