# Agent 记忆效率基准

## 历史 V1 评测范围

`MemoryEfficiencyBenchmarkTest` 使用 12 个会话、每个会话 24 轮，共 288 轮固定基金问答进行确定性 A/B 回放。该用例保留的是 V1 实验参数：20 条消息、8K 历史 Token、最多 12 张事实卡、3K 事实卡 Token，以及按工具类型划分的 5 分钟至 30 天 TTL；它不是当前生产配置的声明。

Baseline 保留全部历史，并为每项事实需求调用工具；Memory 组使用生产 `TokenBudgetChatMemory`，按当前“加载最近有效事实卡”的规则注入事实卡。只有工具名和主题完全匹配、仍在 TTL 内且进入事实卡预算时，才计为一次可复用命中。

这是记忆机制的离线评测，不包含真实 LLM。工具调用下降数据表示确定性 exact-key 复用策略能够避免的调用量，不能表述为线上真实模型调用下降。

## 结果

| 指标 | Baseline | Memory | 结果 |
|---|---:|---:|---:|
| 历史上下文 Token | 353,184 | 236,892 | 降低 32.93% |
| 事实卡注入 Token | 0 | 287,316 | — |
| 历史 + 事实卡总记忆载荷 | 353,184 | 524,208 | 增加 48.42% |
| 全部工具需求/实际调用 | 288 | 96 | 降低 66.67% |
| 重复工具需求/实际重复调用 | 204 | 12 | 降低 94.12% |
| 事实卡复用机会/命中 | 204 | 192 | 命中率 94.12% |

## V1 结论与使用边界

滑动窗口确实减少了 32.93% 的历史上下文 Token，但当前实现会将最近的有效事实卡整体注入，而不是按当前问题检索相关事实卡；在本数据集上，事实卡开销抵消了历史裁剪收益，使总记忆载荷增加 48.42%。因此简历可以引用“历史上下文 Token 降低 32.93%”，但不能表述为“总 Prompt Token 降低 32.93%”。

94.12% 的事实卡命中率和重复调用降低率来自确定性 exact-key 回放。要表述为真实 Agent 效果，还需要使用同一数据集运行开启/关闭事实卡的真实模型 A/B，并从 `agent_run.prompt_tokens`、`agent_tool_call` 和 `agent_fact_card_usage` 统计结果。

复现命令：

```powershell
mvn -pl fund-agent-runtime -am '-DskipTests=false' '-Dtest=MemoryEfficiencyBenchmarkTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
```

机器可读结果生成在 `fund-agent-runtime/target/memory-efficiency-report.json`。

## 真实模型 A/C 评测

2026-09-09 使用项目本地配置的 `qwen3.7-max` 完成 5 个独立场景的真实模型评测。每个场景包含 8 个连续问题：A 组每轮创建新会话并使用信息完整的独立问题；C 组复用同一会话，使用依赖上文的追问，并启用生产环境的聊天历史与事实卡。两组各 40 轮，共执行 80 个用户轮次。

Token 通过 Spring AI `ChatModel` 观测器累计一次用户轮次内的全部模型调用，工具调用和事实卡使用分别取自 `agent_tool_call` 与 `agent_fact_card_usage`，避免只统计最终回答而遗漏 ReAct 中间轮次。回答非空且包含预期类型证据才计为质量通过；生产证据校验拒绝也按质量失败保留在样本中。

| 指标 | A：无上下文/事实卡 | C：完整记忆 | 变化 |
|---|---:|---:|---:|
| 用户轮次 | 40 | 40 | — |
| 质量通过率 | 85.00% | 95.00% | 提升 10 个百分点 |
| 模型调用 | 82 | 55 | 减少 32.93% |
| Prompt Token | 171,113 | 187,666 | 增加 9.67% |
| Completion Token | 41,535 | 29,643 | 减少 28.63% |
| 总 Token | 212,648 | 217,309 | 增加 2.19% |
| 工具调用 | 45 | 15 | 减少 66.67% |
| 重复工具调用 | 24 | 0 | 减少 100.00% |
| 事实卡有效命中 | — | 23 / 25 | 92.00% |

5 个场景的总 Token 变化分别为 `+12.22%`、`+5.56%`、`+4.81%`、`-5.64%`、`-4.36%`。因此当前 8 轮短会话不能支持“记忆节省总 Token”的表述；更准确的结论是，总 Token 基本持平（增加 2.19%）的同时，记忆显著减少模型与工具的重复调用，并提高证据质量通过率。该结果属于固定数据集上的小样本真实模型评测，模型输出具有随机性。

复现真实模型评测需要本地 MySQL 和模型凭据：

```powershell
$env:RUN_MEMORY_AB_EVAL='true'
mvn -pl fund-bootstrap -am '-Dtest=MemoryRealModelAbIT' '-Dsurefire.failIfNoSpecifiedTests=false' '-Dmemory.eval.scenarios=5' test
```

本次机器可读结果保存在 `docs/memory-real-model-ab-report.json`。

## 单会话滑动窗口阈值评测

使用生产配置的 20 条消息与 8000 Token 双阈值，对一个会话连续执行 16 轮真实模型问答。前 10 轮历史从 2 条增长到 20 条；第 11 轮首次发生裁剪，数据库仍保留 20 条消息，当时历史仅为 2898 个估算 Token，因此本次常规基金问答由消息数阈值先触发。第 11～16 轮窗口始终保持 20 条，历史 Token 位于 2302～2898 之间，未接近 8000 Token 阈值。

第 16 轮重新询问第 1 轮的基金公司与基金经理。此时第 1 轮已经离开聊天窗口，但运行记录显示注入了 `get_fund_profile` 事实卡，未再次调用该工具且回答成功，验证了历史裁剪后的早期事实复用。

| 指标 | 结果 |
|---|---:|
| 单会话轮数 | 16 |
| 首次裁剪轮次 | 第 11 轮 |
| 首次触发阈值 | 20 条消息 |
| 首次裁剪时历史 Token | 2898 / 8000 |
| 裁剪后早期事实复用 | 成功 |
| 最终轮资料工具调用 | 0 |

机器可读结果保存在 `docs/memory-window-threshold-report.json`，测试实现为 `MemoryWindowThresholdIT`。
