# Worker 租约与旧执行隔离

每次领取任务在数据库事务中递增 `agent_task_lease.version`，并将任务 ID、Worker ID、世代号一起交给执行器。租约记录在完成、失败、恢复时保留，不能单独清理，否则世代号可能复用。不需要修改现有数据库表结构。

Worker 使用独立虚拟线程执行任务，每隔租约时长的三分之一续租（默认 30 秒租约对应约 10 秒）。续租必须匹配 RUNNING 状态、实例、世代号及未过期的截止时间。JDBC 实现以数据库时间判定，避免 Worker 时钟偏差；内存实现使用传入时间，便于模拟恢复。批量执行会推进时间，不复用整轮开始时的时间戳。

完成、失败、审批等待均要求携带 ClaimedTask。数据库先锁定任务及租约，校验当前世代和有效期，再在同一事务提交结果、幂等记录及事件。过期恢复也使用行锁，避免与心跳续租竞争；直接领取过期 RUNNING 任务同样记录 task.retrying。

研究图通过 CapabilityExecutionContext.persist 将检查点与图事件纳入相同数据库事务。此回调只用于同一数据源的短数据库写入，不允许执行外部网络调用。后续新增能力应在新的工具调用前执行 checkActive，并通过 persist 保存任务进度。无租约的独立能力上下文不能保存持久化进度。

续租返回失败、异常或调度线程中断时，Worker 取消执行 Future 并发送线程中断，关闭执行上下文。图节点和重试工具调用在开始前重新检查租约。即使外部请求不响应取消，旧世代的后续检查点、失败和结果写入仍会被数据库拒绝。

## 发布和边界

上线前停止旧版本 Worker，再启动新版本，避免仍使用无世代号写入接口的旧进程绕过隔离。不要在新旧版本 Worker 混跑期间宣称隔离生效。

这套实现保护当前 DAG 的数据库结果和研究图检查点。已发出的外部请求不能被本地事务撤回；新增外部写操作仍须由下游校验 fencing token，或使用业务幂等键/outbox。成功记录去重不等于外部调用 exactly-once。

## 验证范围

运行项目现有 Maven 测试和编译检查。现有测试覆盖任务领取竞争、过期恢复、审批和正常执行，但不覆盖全部新增世代号隔离和长任务心跳故障场景。本次未新增或修改测试代码。真实 MySQL 并发故障注入需要专用测试环境进一步验证。
