# FundPilot 产品页面优化指引

评审日期：2026-09-05  
评审方式：模拟“大厂页面设计师”与“普通基民代表”双角色讨论，结合当前前端实现审查。  
交付范围：优化方向、优先级、页面要求与验收标准；本次没有修改产品代码。

## 1. 结论与证据边界

目前最需要提升的是任务完成度、数据可信度和信息可读性。建议围绕“找到基金 → 看懂表现与风险 → 加入自选 → 持续跟踪”组织页面，将现有研究能力转化为用户能够理解和完成的操作。

代码中已具备品牌色、卡片、基金查询、净值图、流式回答、自选、组合、研究任务、月报和风险画像等基础。问题集中在功能之间的衔接，以及用户页面仍然呈现接口字段和运行信息。

本次检查了 `fund-web/app` 下的首页、自选、组合、任务、月报、通知、账户、登录页面，以及 `components/AppShell.tsx`、`lib/session.ts`、`app/globals.css`。README 指向的本地 3000 端口实际打开 Grafana，因此没有完成产品实屏、登录态及移动端交互验证。

本文区分三类内容：

- **代码确认**：当前页面与事件逻辑中直接可见的问题。
- **设计建议**：根据用户任务提出的目标方案，需要设计与研发评估。
- **待验证**：运行效果、真实理解程度、接口能力或数据质量尚未验证。

“基民代表”的发言用于模拟需求与质疑，不能视为真实用户访谈结果。本文不涉及具体基金买卖建议。

## 2. 双角色讨论

### 议题一：用户打开首页，最先应该看到什么？

**设计师：** 现有大标题、蓝色 Hero 和 AI 装饰形成了视觉中心，但查询前大量指标为空，基金类型和管理人又重复出现。首屏需要明确一个主任务。

**基民代表：** 我通常是来看自己关注的基金，或者搜索一只基金。我不一定记得代码，也不想每次都从介绍产品开始。

**讨论结论：** 新用户首页以搜索、最近查询、操作示例为主；有自选的用户优先看到自选摘要与最近研究。查询后进入清晰的基金详情状态，收起大型介绍区。现阶段可以先在同一页面实现状态切换，不必一次拆出很多页面。

### 议题二：专业指标应该展示多少？

**设计师：** 展示收益、回撤和比较基准，能帮助页面形成明确的信息层级。

**基民代表：** 我更关心“这个数字是什么意思”“这段时间跌得多不多”。一次出现十几个指标，我还是看不懂。

**讨论结论：** 默认展示少量核心指标，每项都说明区间与口径；专业指标放入展开区域。收益与风险并列呈现。不能把单位净值变化直接包装成包含分红的投资回报。

### 议题三：AI 研究如何让用户放心？

**设计师：** 执行轨迹与引用信息可以解释回答的来源。

**基民代表：** 我想知道它分析的是哪只基金、资料是哪天的、哪些地方还不确定。模型名称和 Token 数帮不了我判断基金。

**讨论结论：** 输入区显示研究对象，回答采用“要点 → 依据 → 风险与不确定性 → 后续问题”的结构。默认展示数据日期与可打开的来源；技术运行信息进入管理员详情。进度保留可理解的阶段文字。

### 议题四：自选和组合该如何区分？

**设计师：** 自选用于关注，组合用于记录实际持仓，需要有不同的页面结构。

**基民代表：** 我点了加入自选，就应该在哪里都能看到。组合页应该先让我看懂资产和盈亏，再让我录入流水。

**讨论结论：** 统一自选的数据与状态；组合页先展示持仓结果，再提供录入和导入操作。建立“关注但未持有”与“已记录持仓”的明确区别。

### 议题五：功能越多，产品感越强吗？

**设计师：** 目前入口较完整，但研究任务、月报、通知依然以状态和标识符为主，用户难以获得结果。

**基民代表：** 我希望通知告诉我发生了什么，月报告诉我这个月有什么变化。出现一串 ID，我不知道下一步做什么。

**讨论结论：** 每个入口都要具备“内容、状态、下一步操作”。先完成主流程，再扩展筛选、对比和提醒能力。

### 议题六：视觉升级先做什么？

**设计师：** 统一字体、间距、图标、卡片与状态色，建立可复用规范。

**基民代表：** 字要看得清，手机上功能要找得到，操作失败要告诉我怎么继续。

**讨论结论：** 先处理阅读、导航、状态与点击反馈，再优化装饰。品牌蓝可保留，涨跌色独立定义；颜色必须配合正负号和文字说明。

## 3. 优先级总表

P0：影响数据理解、对象一致性或核心流程，建议作为下一轮改版的发布门槛。  
P1：显著提升使用效率和结果可读性，在主流程修复后推进。  
P2：进一步提升研究效率与持续使用价值。

| 编号 | 优先级 | 优化项 | 当前问题与依据 | 预期结果 |
|---|---|---|---|---|
| U01 | P0 | 研究对象与查询状态一致 | 首页发送消息仅包含会话 ID 和文本；从内嵌自选切换基金只更新资料，未重新获取净值 | 名称、图表、AI 研究对象一致 |
| U02 | P0 | 统一自选体验 | 首页写本地临时自选，独立页读取服务端；首页列表仅存在组件状态中 | 添加、刷新、登录后结果可理解且一致 |
| U03 | P0 | 组合记录与数据展示 | 持仓收益直接 JSON 输出，记录日期固定、数字有预填值 | 用户能核对记录，也能看懂持仓与收益 |
| U04 | P0 | 指标口径与真实状态 | 单位净值首尾变化标为近一年；状态默认“已连接”或“正常”，错误也使用同一绿点 | 不误读指标或服务状态 |
| U05 | P1 | 搜索与首页层级 | 仅数字搜索，默认代码，查询前多个空卡片与大幅介绍区 | 新用户知道如何开始，老用户更快回访 |
| U06 | P1 | 净值与表现图表 | 没有时间切换、纵轴数值、点位详情；图表按样本序号分布 | 用户可读出时间、数值和区间口径 |
| U07 | P1 | AI 回答与进度 | 暴露运行术语；只展示最近四条消息；证据标签仅 title 显示 ID | 回答可读、来源可查、历史可回看 |
| U08 | P1 | 研究任务和月报结果 | 任务以 DAG、事件为主；月报仅列表状态与 run ID | 用户能查进度、恢复任务、打开结果 |
| U09 | P1 | 通知和风险画像 | 通知显示规则 ID 与 fingerprint；画像直接 JSON 输出 | 用户理解变化并能采取下一步操作 |
| U10 | P1 | 导航与移动端 | 无当前路由高亮；账户入口未被导航渲染；窄屏隐藏部分导航 | 页面定位明确，手机保留全部功能入口 |
| U11 | P1 | 表单与反馈系统 | 多处缺少常驻字段标签和提交中保护；登录成功固定回首页 | 操作可预期，失败可恢复 |
| U12 | P2 | 对比与持续跟踪 | 尚缺直观基金对比与连贯跟踪入口 | 从单次查询发展为持续研究 |

## 4. 分项优化要求与验收

### U01：所有区域围绕同一个研究对象

**代码确认：** `app/page.tsx` 的提问请求未明确附带当前基金代码；默认问题使用“这只基金”。内嵌自选按钮更新 `fund` 与 `code`，没有更新 `points`。后端是否自行补充上下文尚未验证。

**优化要求：**

- 为查询中的输入值与已加载的基金分别管理状态，详情标题、净值、图表绑定同一次查询结果。
- 切换基金时重新加载数据；加载期间不能将上一只基金的曲线挂在新名称下。
- AI 输入区显示“正在研究：基金名称 / 代码”。发送时明确传递对象，接口暂不支持结构化上下文时，也要在用户可见的提问内容中说明对象。
- 没有对象时，将默认问题改为“输入基金名称或代码后开始研究”。比较多个对象时列出全部基金。
- 查询错误放在搜索区附近；保留旧结果时明确标注其对应基金。
- 处理连续查询的响应顺序，防止较早请求覆盖较新选择。

**验收：** 连续查询 A、B，包括让 A 的响应晚于 B，最终所有资料与图表均属于 B；从自选进入 B 结果一致；问“这只基金”时能确认请求对应 B；失败时不出现混合数据。

### U02：把“加入自选”做成完整闭环

**代码确认：** 首页 `add` 仅调用本地保存；独立自选页读取服务端分组，提供手动合并按钮；首页没有从本地恢复列表。独立页主要展示代码，没有名称、净值与研究入口。

**优化要求：**

- 游客添加后明确提示“已保存在此设备”；登录用户添加到服务端所选分组。
- 登录后如存在本地自选，显示数量及合并入口，并反馈新增、重复和失败结果。
- 所有自选入口使用同一套状态；已加入时显示“已自选”，支持移除并提供撤销。
- 列表至少包含名称、代码、类型、最新净值、净值日期、查看详情操作。涨跌数据需在口径确认后接入。
- 无自选时显示搜索入口；尚未登录时说明本地与云端保存的差异。

**验收：** 游客添加后刷新不丢失；登录合并不重复；登录用户从首页添加后在独立页可见；移除结果一致；数据加载失败与真正空列表呈现不同状态。

### U03：组合页面以“资产和持仓”开场

**代码确认：** `app/portfolios/page.tsx` 用 `pre` 输出持仓与收益，流水日期固定为 2026-01-02 / 2026-01-03，份额、金额、净值预填为 10、100、10；切换组合没有同步清空或加载结果。

**优化要求：**

- 页面顺序调整为：组合选择 → 摘要 → 持仓表 → 流水与导入入口。
- 摘要优先展示已确认可计算的总资产、持有收益、累计收益及估值日期；先明确各指标区别和数据来源，缺失时展示原因。
- 持仓表展示基金名称/代码、份额、估值、成本及可用收益字段，数值右对齐并标单位。
- 将“追加申购”改为“记录买入”，说明这是记账操作。日期由用户选择，金额、份额、费用等不预填虚构业务值。
- 切换组合时自动刷新属于该组合的数据；写入成功后刷新摘要、持仓及流水。
- 导入流程提供模板与字段说明、行级预览、错误行原因、最终导入摘要；更换文件或组合后，原预检结果失效。
- 录入必须有常驻标签、必填提示及一致性校验；不要将接口字段名作为用户文案。

**验收：** 普通用户页面没有 JSON；录入日期与保存结果一致；切换组合不会残留上一组合数据；未通过预检不能提交；重复点击不产生重复记录；导入后可核对数量和持仓变化。

### U04：数据口径与状态必须可信

**代码确认：** 图表用所选样本的首尾单位净值计算变化，却固定标注“近一年”；默认连接状态未依据健康检查；状态指示点对错误仍使用绿色。富文本中存在根据特定文字显示“引用证据已校验”的逻辑。

**优化要求：**

- 明确区分单位净值变化、区间收益和实际持有收益；未接入可靠复权/分红口径前，将当前曲线指标标为“区间单位净值变化”。
- 所有区间数字注明实际起止日期；不足一年时提示“历史不足一年”，不让标签暗示完整年度。
- 净值日期、持仓披露日期、行情时间各自标注，避免笼统的“实时”覆盖不同数据。
- 未检查时不显示“服务正常”；待查询、更新中、已更新、部分数据缺失、失败使用不同文字和样式。
- “证据已校验”只能由真实校验状态驱动，不能由回答中的字符串推断。

**验收：** 使用不足一年、零数据、部分失败、陈旧数据等样本检查；没有收益数据时不使用 0% 替代；每个数值都能找到口径和日期；失败状态不会仍显示成功语义。

### U05：首页与搜索围绕下一步行动

**优化要求：**

- 搜索框提供常驻标签或可访问名称，以及“输入基金名称或 6 位代码”的提示；名称搜索需确认后端检索能力，未支持时不承诺。
- 移除默认真实代码，提供明确标注的查询示例。支持清空、加载状态、无结果提示与键盘选择。
- 搜索结果区分名称相近、不同份额类别的产品，展示名称、代码、类型及必要的份额标识。
- 初次访问展示一段简短用途说明、搜索和示例问题，收起无数据的指标卡。
- 查询成功后用紧凑基金摘要替代大型 Hero，将“加入自选”和“问 AI”放在名称附近。
- 删除基金类型、管理人在首屏反复占据独立卡片的冗余，把详细资料放入资料区。

**验收：** 新用户无需知道基金代码也有明确起步路径；若仅支持代码，输入要求清楚；查询成功后首屏包含基金身份、有效关键数据和主要操作；失败后可以直接修改并重试。

### U06：图表要能回答具体问题

**优化要求：**

- 提供近 1 月、3 月、6 月、1 年和全部等合理区间，按数据能力逐步启用。
- 增加纵轴数值、单位与实际日期范围，鼠标悬停和触摸能查看日期与对应数值。
- 横轴按日期组织；数据缺口需区分非交易日和异常缺失，不能通过连线掩盖异常。
- 比较模式明确数据类型；单位净值曲线与收益率曲线不能直接混用。
- 如加入比较基准，说明名称、口径、时间范围；无匹配数据时不强行绘制。
- 在图表附近提供简短指标解释，例如“最大回撤：所选区间从阶段高点到后续低点的最大跌幅”，并说明历史指标不代表未来幅度。

**验收：** 区间切换同步更新曲线、数字、日期和解释；触摸可读取点位；无数据、单点、缺失区间与短历史均有清楚反馈。

### U07：让 AI 输出成为可阅读的研究结果

**优化要求：**

- 回答先提供三条以内核心观察，再展示依据、风险及资料缺口，详细分析可展开。
- 提供与当前基金相关的问题快捷入口，如“查看区间回撤”“了解持仓分布”。不要默认生成确定性买卖指令。
- 引用可以打开来源详情，包含文档名称、发布/数据日期、对应摘录与可用原文链接；只有证据 ID 不足以让用户核对。
- 运行进度使用“获取资料 → 分析表现 → 整理结论”等阶段，准确呈现部分失败，不以日志条数伪造百分比。
- 模型、Prompt、Token、工具名和账本信息进入管理员详情；用户保留数据截止、来源及必要的耗时说明。
- 支持查看完整会话，至少提供“查看更早消息”；失败保留原问题并提供重试。停止生成的语义要与后端是否停止任务保持一致。
- 在提交前说明登录要求；登录成功回到研究对象并保留草稿。

**验收：** 超过四条的历史仍可访问；点开引用可定位具体依据；失败后不需要重新输入；未选择基金时不会假定“这只基金”；刷新后的会话恢复需单独验证存储能力。

### U08：研究任务和月报要呈现成果

**代码确认：** 研究任务页展示 DAG、执行模式和事件，没有可见的历史任务列表与持续刷新逻辑；月报列表没有打开报告内容的操作。

**优化要求：**

- 任务列表展示研究主题、基金对象、创建时间、中文状态与结果入口；具体任务提供阶段进度。
- 已完成可查看报告；进行中可取消；失败显示原因与重试方式；刷新后能恢复任务。
- 需要用户确认时展示具体操作、影响和可选项，不只有“审批通过”按钮。
- 月报生成前选择月份和研究范围，展示将使用的组合/自选；若依赖尚未满足，明确指出缺什么。
- 月报完成后可阅读要点、持仓或自选变化、风险观察与数据日期；分享、导出作为后续能力按需建设。
- 异步任务通过轮询或订阅更新状态，具体机制由现有后端能力决定。

**验收：** 创建任务后无需手工重新提交即可看到状态变化；刷新仍能找回任务；完成任务可打开实际内容；失败和取消的后续操作明确。

### U09：通知与画像说用户能理解的话

**优化要求：**

- 通知展示标题、发生时间、相关基金/组合、摘要及详情入口。规则 ID 和指纹放入运维信息。
- 提供未读/已读反馈；无通知时说明以后哪些变化会出现在这里。
- 风险画像用结果卡展示类型、评估日期、结果说明与重测入口，不直接输出接口响应。
- 问卷说明用途，显示完成进度，遗漏项定位到具体题目；不虚构完成时长。
- 用户可从账户入口查看画像；研究结果中引用画像时说明其评估日期及适用范围。

**验收：** 用户可仅凭通知标题与摘要判断是否需要查看；画像不显示 JSON；未完成的问卷不能误显示已完成；旧结果与新评估状态可区分。

### U10：建立完整的导航与视觉规范

**代码确认：** `AppShell` 只渲染 `links.slice(0,6)`，账户入口未渲染，头像也没有账户链接；没有当前页选中态。560px 以下隐藏第四项及以后的导航，未提供替代入口。

**优化要求：**

- 桌面导航提供当前页高亮与可访问的当前页状态；头像进入账户菜单。
- 每页使用自己的标题与简短说明，例如“我的自选”“组合概览”；通用品牌标语仅保留在合适的介绍场景。
- 移动端采用底部导航或可展开菜单，所有主要功能可达。
- 建议正文 14–16px，辅助文字 12–13px；重要日期与风险信息不能使用 10px 弱对比文字。
- 以 4/8px 步进统一间距，卡片圆角与边框保持一致；一屏突出一个主要动作。
- 使用统一图标集，减少 Unicode 符号在不同设备上的形态差异。
- 品牌蓝用于操作；涨跌建议采用适合目标用户的红涨绿跌默认方案，并配合正负号与文字，验证用户习惯后确认。
- 按钮与输入框有清楚的焦点态；重要触控区域建议至少 44px；对比度、键盘操作和读屏需实测。

**验收：** 在 360、390、768、1440px 宽度验证；除必要的数据表区域外无横向溢出；所有页面可从导航到达；仅键盘可完成搜索和主要表单；涨跌不依赖单一颜色辨认。

### U11：统一加载、空白、错误与成功反馈

**优化要求：**

- 每个数据模块具备首次加载、成功有数据、成功无数据、部分缺失、失败和登录受限状态。
- 列表使用结构化占位或简洁加载提示，不能在加载期间直接宣告“没有数据”。
- 错误就近展示，给出可执行的下一步；不要将后端原始响应直接塞进页面顶部状态胶囊。
- 提交按钮在请求期间防重复点击；长任务明确进入后台后的查看位置。
- 成功反馈说明结果，例如“已加入默认分组”，并提供查看入口。
- 登录保留返回路径、查询对象和草稿；到期后恢复会话失败时明确引导重新登录。
- 全部输入增加常驻标签，避免值填入后无法辨认字段；图标按钮有可访问名称。

**验收：** 弱网、401、403、500、空列表、重复点击等场景均有合理反馈；成功提示与最终列表数据一致；用户失败后能在当前上下文继续。

### U12：主流程稳定后的增强项

- 支持选择 2–3 只基金比较，以相同区间、同类口径展示收益、回撤、费用等已确认数据。
- 自选支持按类型分组、最近研究和更新情况查看，优先补全已有分组功能。
- 根据真实可用数据建立关注事项，例如“新报告已披露”，每条变化能追溯依据。
- 对持仓变动、经理变更等提醒，先确认数据覆盖和更新时间，再决定支持范围。
- 结果保存、导出和月度回顾应复用现有研究成果，减少用户重复提问。

**验收：** 比较清楚标明口径不一致和缺失数据；提醒可进入对应详情；用户可以关闭提醒；未经数据支持不生成看似实时的变化。

## 5. 推荐页面组织

以下是目标信息顺序，属于文字线框，不代表已完成视觉设计。

### 首页：发现与继续研究

1. 顶部导航、账户入口和全局搜索。
2. 新用户：简短说明、示例查询；已有自选用户：自选摘要、最近研究。
3. 需要关注的已核实更新；没有更新时不制造紧迫感。
4. AI 研究入口和常见研究问题。

### 基金详情：身份 → 表现与风险 → 依据 → 行动

1. 基金名称、代码、类型、数据日期，以及加入自选操作。
2. 已有可靠数据支持的净值、区间表现和风险摘要。
3. 可切换区间的图表与指标解释。
4. 持仓、基金经理、费用及资料来源，按接口可用性逐步启用。
5. 带明确研究对象的 AI 输入区与历史研究结果。

### 组合：结果 → 构成 → 记录

1. 组合选择与估值日期。
2. 资产和收益摘要。
3. 持仓明细与可解释的风险分布。
4. 交易记录、记一笔、导入记录。
5. 组合研究与月报入口。

## 7. 实施顺序与依赖

### 第一阶段：修复核心一致性

完成 U01–U04，同时补上账户可达性和移动端替代导航。先解决对象错位、自选保存、记账日期、指标口径和虚假正常状态。无需等待完整视觉改版。

### 第二阶段：完成主要页面体验

推进 U05–U11。先确定信息层级、公共反馈组件与视觉规范，再逐页落地。优先级为首页/详情、自选、组合、AI、任务/月报、通知/账户。

### 第三阶段：建设持续使用能力

推进 U12，并根据真实任务测试调整首页与自选的排序。对比、提醒、导出分别确认数据与接口能力。

| 可主要在前端处理 | 需要核实后端或数据支持 |
|---|---|
| 页面标题、导航选中态、账户入口、移动菜单 | 名称检索及份额类别信息 |
| 常驻标签、加载反馈、错误位置、禁用提交 | 收益口径、分红复权、风险指标 |
| 同一基金状态管理、查询响应顺序保护 | 研究对象如何进入会话上下文 |
| 现有字段的卡片与表格展示 | 证据详情与原文定位 |
| 草稿和返回路径保留 | 任务历史、结果读取及持续状态更新 |
| 隐藏普通用户不需要的运行字段 | 通知正文、已读状态与提醒配置 |

新增指标或页面能力前先明确接口契约；不得为了视觉完整填充虚构收益、持仓或更新状态。暂不可用的能力应给出缺失说明或暂不展示入口。

## 8. 可用性验证与发布检查

建议邀请 5–8 位覆盖新手、经常查看自选、已有多基金持仓的用户进行形成性测试。该样本用于发现问题，不能据此推断全部基民的偏好。

| 任务 | 观察重点 | 建议目标（待测试校准） |
|---|---|---|
| 找到指定基金并确认份额类别 | 是否依赖记忆代码、是否选错 | 30 秒内完成且对象正确 |
| 解释图表区间、涨跌和数据日期 | 是否把净值变化误读为持有收益 | 能说清口径与日期 |
| 加入自选并刷新、登录后找回 | 是否担心丢失、是否出现重复 | 结果一致，不需口头帮助 |
| 为当前基金发起研究并查来源 | 是否明确对象、能否打开依据 | 对象一致，来源可定位 |
| 记录一笔买入并核对持仓 | 是否理解字段、日期和记账性质 | 数据正确且用户能复核 |
| 在手机查看研究任务与账户 | 是否存在隐藏入口 | 全部主要功能可达 |

发布前逐项检查：

- [ ] U01–U04 的验收场景通过，数据对象和口径无混淆。
- [ ] 普通用户页面不直接展示 JSON、内部标识符及无必要的运行术语。
- [ ] 查询、自选、组合、研究结果各自具备有效的下一步入口。
- [ ] 空数据、加载、失败、受限状态可区分，重试保留上下文。
- [ ] 手机端无不可达导航，关键字段与按钮可阅读、可操作。
- [ ] 所有新展示指标可追溯数据与计算口径，引用状态来自实际校验。
- [ ] 数据缺失与失败不伪装为零值、成功或正常。
- [ ] 发布前补做真实页面、登录态、弱网和移动端验证。
